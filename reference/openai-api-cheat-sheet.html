3. Sous le Capot du Serveur d'Inférence : Du JSON Applicatif aux Tokens GPU (Étape 1 & Étape 3)

Couche Technique Ce qui se passe côté Serveur (vLLM / TGI / OpenAI) Impact Mathématique & Matériel (GPU)
1. Entraînement des Rôles & Outils
(Pré-entraînement → SFT → Tool Calling)		 Le modèle apprend un Chat Template (balises spéciales <|im_start|>, <|im_end|>, <tool_call>, <tool_response>). Loss Masking : Durant le SFT, les questions user sont masquées dans la fonction de coût. Le LLM n'est entraîné à prédire que les tokens situés après <|im_start|>assistant.
2. Aplatissement & Parsing
(Conversion JSON ↔ ChatML)		 Le moteur Jinja2 écrase le JSON HTTP (messages[] + tools[]) en une chaîne de texte plate à l'aller, et parse <tool_call>...</tool_call> en finish_reason: "tool_calls" au retour. Le GPU ne voit jamais la structure JSON applicative OpenAI : il ne consomme et ne produit qu'un flux plat d'identifiants de tokens.
3. Cycle GPU en Temps Réel
(Prefill vs Decode)		 Phase 1 (Prefill) : Lecture parallèle de tout l'historique.
Phase 2 (Decode) : Écriture séquentielle token par token jusqu'à <|im_end|>.		 KV Cache (Prefix Caching) : Le Prefill stocke les matrices d'attention en mémoire vidéo (VRAM). Au tour suivant (retour role: "tool"), seuls les nouveaux tokens sont calculés !

4. Matrice d'Activation : Tool Calling Classique vs Code Mode (execute)

Critère Technique Situation A : "codeMode": false (Étapes 2 à 4) Situation B : "codeMode": true (Étape 6)
Déclaration dans tools[] Tous les schémas JSON de tous les outils MCP sont injectés dans tools[]. Un seul méta-outil dans tools[] : execute (signatures TS compactes dans system).
Orchestration Multi-Outils 15 appels d'outils = 15 allers-retours HTTP complets avec le serveur LLM. Le LLM écrit un script JS async exécuté en 1 seul aller-retour dans la sandbox locale.
Empreinte sur la Context Window Tous les JSON bruts intermédiaires s'accumulent dans messages[]. Les payloads intermédiaires restent en RAM locale ; seul le return final entre dans role: "tool".

Caractéristique Chat Completions (/v1/chat/completions) Responses API (/v1/responses)
Statut Industriel Standard universel multi-fournisseurs (OpenCode, Cursor, LiteLLM, vLLM, Ollama, OpenRouter). Nouvelle API unifiée propre à la plateforme cloud d'OpenAI (Étape 13).
Structure d'Entrée & Sortie Entrée : messages: [{"role": "system"|"user"|"assistant"|"tool", "content": "..."}]
Sortie : choices[0].message & response_format		 Entrée : instructions + input + previous_response_id
Sortie : output[] & text.format
Exécution des Outils 100% gérée par la boucle cliente (réception de tool_calls → retour role: "tool"). Hybride : outils hébergés côté serveur OpenAI (web_search, file_search, code_interpreter) + fonctions clientes.
