La Boucle Agentique ReAct : Rôle tool & Permissions

Answer

Le patron ReAct (Reason + Act + Observe) anime l'agent dans une boucle while locale. Le client intercepte l'appel, vérifie les autorisations et réinjecte le résultat avec role: "tool".

  1. L'observation du résultat physique est transmise au LLM avec role: "tool" et le tool_call_id associé.
  2. Le moteur de gouvernance filtre chaque outil selon trois politiques : allow (automatique), ask (confirmation humaine) ou deny (refus immédiat).
  3. En cas d'erreur d'exécution système, le message d'erreur est renvoyé dans le corps du rôle tool pour permettre au modèle de s'auto-corriger.
  4. Un compteur d'itérations maximales protège le système contre les boucles infinies et la surconsommation de jetons.

La boucle s'exécute localement sur la machine hôte sans état conservé côté serveur d'inférence.

  1. 1. Raisonnement (Reason) ↗

    Le modèle linguistique analyse le problème et génère une intention d'action structurée.

  2. 2. Contrôle de Sécurité (Gate) ↗

    L'orchestrateur vérifie si la commande nécessite une confirmation explicite de l'utilisateur.

  3. 3. Exécution Physique (Act) ↗

    Le script système ou la commande locale est exécuté avec isolation de l'environnement.

  4. 4. Observation (Observe) ↗

    Le résultat brut ou l'erreur est réinjecté avec role: "tool" pour le tour suivant.
