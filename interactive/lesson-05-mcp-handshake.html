Standardisation des Outils : Le Protocole MCP (JSON-RPC 2.0)

Long image

A

Answer

Le Model Context Protocol découple l'agent de ses sources de données via un protocole JSON-RPC 2.0 standardisé sur flux standard (stdio) ou HTTP.

  1. La phase initialize négocie les capacités du client (roots, sampling) et du serveur (tools, resources).
  2. La découverte dynamique via tools/list permet au client de charger les schémas JSON sans modifier le code de l'agent.
  3. L'invocation s'effectue via tools/call, avec retour immédiat du résultat sous forme de texte ou de ressource binaire.
  4. La capacité sampling permet à un serveur MCP de demander une inférence au LLM sans posséder de clé API propre.

Comment s'articulent les 4 phases du cycle de vie MCP ?

Le protocole standardise les échanges entre l'application hôte et les serveurs d'outils externes.

Diagram structure
  • Client OpenCode client
  • Serveur MCP SQLite server
  • client → server · initialize (roots, sampling)
  • server → client · initializeResult (tools, resources)
  • client → server · notifications/initialized
  • client → server · tools/list
  • server → client · listResult (schemas JSON stricts)
  • client → server · tools/call (query, arguments)
  • server → client · callResult (lignes SQL formatees)

Déchiffrage des capacités négociées

roots.listChanged informe le serveur lorsque l'utilisateur ouvre ou ferme des dossiers dans l'espace de travail. sampling autorise le serveur MCP à solliciter le modèle d'inférence du client en toute sécurité. tools.listChanged permet au serveur d'ajouter ou de retirer dynamiquement des outils en cours d'exécution.

La configuration s'effectue dans le fichier opencode.json ou mcp.json.
