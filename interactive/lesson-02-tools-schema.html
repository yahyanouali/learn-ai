L'agent expose ses capacités au modèle via le tableau standard tools[] : chaque outil est décrit par un schéma JSON strict spécifiant types, contraintes et descriptions sémantiques.

  1. La description de l'outil agit comme une consigne directe orientant le choix du modèle.
  2. La bibliothèque Zod permet de générer automatiquement des schémas JSON Schema compatibles draft 2020-12.
  3. Le paramètre tool_choice force, autorise ou interdit l'invocation d'outils par le modèle.
  4. L'option parallel_tool_calls permet au modèle d'émettre plusieurs appels indépendants en une seule passe.

Comment le runtime compile-t-il la définition d'un outil ?

Le runtime transforme une signature de fonction typée en contrat d'interface pour le modèle de langage.

  1. 1. Implémentation Locale ↗

    La fonction est codée en TypeScript avec ses types natifs et sa logique métier.

  2. 2. Schématisation Zod ↗

    Les paramètres d'entrée sont encapsulés dans un objet Zod précisant les formats requis.

  3. 3. Export JSON Schema ↗

    Le runtime sérialise l'objet Zod au standard JSON Schema avec additionalProperties: false.

  4. 4. Exposition au Modèle ↗

    Le payload HTTP est envoyé au LLM pour qu'il identifie quand utiliser cet outil.
