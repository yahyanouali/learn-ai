L'architecture OpenCode V2 s'appuie sur le standard @opencode/plugin pour intercepter les événements de la boucle agentique et implémenter des garde-fous de sécurité en entreprise.

  1. Règle 1 : Les hooks V2 ignorent les valeurs retournées ; toute modification doit s'opérer par mutation sur place via replaceInPlace.
  2. Règle 2 : Le résultat d'un outil dans execute.after possède une enveloppe structurée (event.result.content[0].text).
  3. Règle 3 : Le contexte est isolé par espace de travail au sein de setup(ctx), avec une fonction de nettoyage à la fermeture.
  4. Cursor propose un mécanisme comparable via le fichier .cursor/hooks.json exécutant des scripts Node.js externes.

Comment un plugin intercepte-t-il les commandes sensibles ?

Le plugin inspecte et mute les arguments avant tout lancement de processus physique.

Les 3 Règles Fondamentales d'OpenCode V2

Règle n°1 : Ne jamais faire return newCommand. Seule la méthode event.replaceInPlace() modifie le flux. Règle n°2 : Dans execute.after, inspecter event.result?.content?.[0]?.text pour manipuler la sortie. Règle n°3 : Renvoyer une fonction de nettoyage return () => cleanup() pour libérer les ressources allouées.
