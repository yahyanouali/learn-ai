Enseigner des Savoir-Faire Métier : Les Skills (SKILL.md) & Progressive Disclosure

Pourquoi ne faut-il jamais copier 40 procédures opérationnelles (runbooks, migrations SQL, revues de sécurité) dans AGENTS.md ? Découvrez le pattern de Divulgation Progressive (Progressive Disclosure).

📖 Fil Rouge Architectural • Chapitre 8
À l'Étape 7, nous avons placé nos règles globales dans AGENTS.md. Très vite, toute l'entreprise veut y ajouter ses procédures spécialisées : comment migrer une base Prisma, comment auditer un contrat Solidity, comment déployer sur Kubernetes, comment rédiger un post-mortem... Notre AGENTS.md atteint 55 000 tokens ! Il dépasse le budget, dilue l'attention du modèle (phénomène de Lost in the Middle) et ralentit chaque question triviale.
🔴 Le Problème Technique : Surcharge Cognitive & Dilution d'Attention
Les Rules (AGENTS.md) sont conçues pour des contraintes permanentes et courtes. Si vous y injectez 30 guides procéduraux de 1 500 tokens chacun, 97% de ces instructions sont totalement hors-sujet pour la tâche courante, mais occupent la Context Window et dégradent la précision d'attention du Transformer.
🟢 La Solution Architecturale : Les Skills & Progressive Disclosure
Un Skill est un dossier modulaire (SKILL.md + scripts/ + references/). Au démarrage, l'agent applique le pattern de Progressive Disclosure (chargement paresseux en 3 niveaux) :
1. Niveau 1 (Indexation) : Seuls name + description (~25 tokens) sont listés dans le catalogue de l'outil skill.
2. Niveau 2 (Activation) : Si la tâche correspond, le LLM appelle l'outil skill(name) qui charge le corps de SKILL.md dans role: "tool".
3. Niveau 3 (Exécution) : Le LLM n'exécute les scripts de scripts/ ou ne lit references/ qu'en cas de besoin.

1. Anatomie Standardisée d'un Skill (Standard Agent Skills)

Le format Agent Skills est un standard ouvert supporté nativement à la fois par OpenCode, Cursor et Claude Code. Un skill est un répertoire portant le nom de la compétence (en kebab-case) et contenant obligatoirement un fichier SKILL.md : 

.agents/skills/prisma-migration-safe/
├── SKILL.md                        # Frontmatter YAML (name, description) + Runbook Markdown
├── scripts/
│   └── check-destructive-sql.sh    # Script exécutable vérifiant les DROP TABLE / COLUMN
└── references/
    └── zero-downtime-patterns.md   # Documentation approfondie lue uniquement si nécessaire

Code Source de SKILL.md

---
name: prisma-migration-safe
description: >-
  Génère et vérifie une migration SQL Prisma sans interruption de service (Zero-Downtime).
  À utiliser dès que l'utilisateur modifie schema.prisma ou demande une migration de base de données.
---

# Procédure de Migration Prisma Zero-Downtime

Lorsque tu dois créer ou valider une migration de base de données :
1. Génère le fichier SQL en mode brouillon sans l'appliquer :
   `bunx prisma migrate diff --from-schema-datamodel prisma/schema.prisma --script > /tmp/draft.sql`
2. Exécute le script de vérification : `./scripts/check-destructive-sql.sh /tmp/draft.sql`.
3. Si une opération destructive (`DROP COLUMN`, `ALTER COLUMN TYPE`) est détectée, consulte obligatoirement le guide `./references/zero-downtime-patterns.md` (Pattern Expand & Contract).

Contrôle de Permissions & Invocation Dans opencode.jsonc : permission sur la clé "skill" (allow, ask, deny par motif de nom) ; invoqué via l'outil natif skill. Activé automatiquement par matching sémantique sur description ou invoqué manuellement via commande slash /nom-du-skill dans le chat.
⚙️ Contrôle des Skills dans OpenCode (opencode.jsonc)
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "skill": {
      "*": "allow",
      "prisma-migration-safe": "allow",
      "prod-deploy-*": "ask"
    }
  }
}
