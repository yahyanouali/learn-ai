Programmer le Runtime : Plugins JS/TS OpenCode (@opencode-ai/plugin) vs Hooks Cursor

Les Rules et les Skills guident le modèle en langage naturel, mais ils restent probabilistes. Pour imposer une logique 100% déterministe au cœur de la boucle agentique, nous devons programmer le runtime lui-même.

📖 Fil Rouge Architectural • Chapitre 10
Maintenant que vous maîtrisez l'API LLM (Étape 1), les `tools[]` (Étapes 2-4), MCP (Étape 5), les Rules (Étape 7), les Skills (Étape 8) et les Sous-Agents (Étape 9), toutes les pièces du puzzle s'assemblent enfin ! Que se passe-t-il si, malgré une consigne dans `AGENTS.md`, le LLM tente d'appeler un outil destructeur, ou si un outil MCP lit un fichier contenant un secret `ghp_...` et s'apprête à l'envoyer dans le cloud ? Les consignes Markdown ne suffisent plus : il nous faut des intercepteurs en code réel branchés sur le cycle de vie de l'agent.
🔴 Le Problème Technique : L'Insuffisance des Consignes Probabilistes
Écrire « Ne divulgue jamais de clés API et ne fusionne jamais une PR » dans AGENTS.md est une barrière souple (Soft Guardrail). Un LLM reste un modèle statistique : sous l'effet d'un contexte long ou d'une injection de prompt, il peut ignorer la règle. De plus, quand un outil renvoie sa sortie vers role: "tool", le LLM ne peut pas « s'empêcher de voir » un secret déjà présent dans le résultat !
🟢 La Solution Architecturale : Plugins JS/TS In-Process & Lifecycle Hooks
OpenCode permet de charger des modules JavaScript / TypeScript (~/.config/opencode/plugins/*.ts) via le SDK @opencode-ai/plugin (tandis que Cursor utilise .cursor/hooks.json). Ces plugins s'exécutent de manière déterministe à chaque étape de la boucle (avant l'envoi du prompt, avant l'exécution d'un outil, et après l'exécution d'un outil) pour créer des outils natifs, muter les arguments ou purger les secrets en mémoire vive.

1. Comment fonctionne le Moteur de Plugins JS/TS d'OpenCode ?

Dans OpenCode, tout fichier .ts ou .js déposé dans ~/.config/opencode/plugins/ (global) ou .opencode/plugins/ (projet) est exécuté directement par le runtime Bun/Node au démarrage : 

~/.config/opencode/
├── package.json                     # Dépendance : "@opencode-ai/plugin": "1.14.49"
├── opencode.jsonc                   # Configuration globale (modèles, serveurs MCP, permissions)
└── plugins/                         # Modules JS/TS chargés en mémoire vive au démarrage
    ├── git-helper.ts                # Partie 1 : Plugin léger (Outil Zod + System Transform)
    ├── openintercept-v2.ts          # Partie 2 : Pare-feu d'interception V1/V2 (Pre/Post Tool)
    └── orca-opencode-status.js      # Télémétrie temps réel des événements de session

PARTIE 1 • Le Plugin JS/TS Léger : Comprendre les Bases du SDK

Commençons par un plugin minimaliste et autonome de 35 lignes pour assimiler les fondations du SDK @opencode-ai/plugin. Au chargement, OpenCode appelle votre fonction exportée en lui injectant l'objet PluginInput : { client, project, directory, worktree, serverUrl, $ }.

Code Source Complet : ~/.config/opencode/plugins/git-helper.ts

import { type Plugin, tool } from "@opencode-ai/plugin"

// Un plugin V1 est une fonction async recevant le contexte du projet et le BunShell ($)
export const GitHelperPlugin: Plugin = async ({ directory, worktree, $ }) => {
  return {
    // 1. Déclaration d'un outil custom en TypeScript (converti automatiquement dans tools[])
    tool: {
      git_quick_info: tool({
        description: "Récupère la branche Git active et les 3 derniers commits du dépôt",
        args: {
          // tool.schema expose Zod (z) pour générer le JSON Schema (vu à l'Étape 2)
          includeStat: tool.schema.boolean().describe("Inclure le résumé des fichiers modifiés (--stat)"),
        },
        async execute(args, context) {
          // '$' exécute la commande shell de manière sécurisée dans context.directory
          const branch = await $`git -C ${context.directory} branch --show-current`.text()
          const flag = args.includeStat ? "--stat" : "--oneline"
          const log = await $`git -C ${context.directory} log -n 3 ${flag}`.text()

          return [
            `Dossier : ${context.directory} (Worktree: ${worktree})`,
            `Branche : ${branch.trim()}`,
            `Commits :\n${log.trim()}`,
          ].join("\n")
        },
      }),
    },

    // 2. Hook léger : injecte dynamiquement du contexte dans messages[0] (role: "system")
    "experimental.chat.system.transform": async (_input, output) => {
      // RÈGLE D'OR : On mute le tableau output.system directement en mémoire (in-place) !
      output.system.push(
        `[Plugin GitHelper] Dépôt actif : ${directory}. Appelle 'git_quick_info' avant tout commit.`
      )
    },
  }
}

export default GitHelperPlugin
Pourquoi muter output au lieu de faire return ? (Mutation In-Place)
Dans le moteur d'OpenCode (V1 comme V2), les hooks sont appelés en cascade selon le pattern Middleware et leurs valeurs de retour sont ignorées. Le moteur conserve la référence mémoire de l'objet output initial : toute modification doit donc se faire in-place (ex: output.system.push(...), output.temperature = 0.1, ou suppression/réassignation des clés de output.args).

PARTIE 2 • Industrialiser en Production : Pare-Feu JS/TS (V1/V2), MCP & Skill

En production (à l'image de openintercept.ts et openintercept-v2.ts), nous industrialisons notre architecture en faisant coopérer :

  • Un Serveur MCP dans opencode.jsonc (Étape 5) qui fournit les outils GitHub.
  • Un Skill dans .agents/skills/review-pr/SKILL.md (Étape 8) qui décrit la méthodologie d'audit.
  • Un Plugin JS/TS Industrialisé (security-interceptor.ts) compatible OpenCode V1 (CLI) et V2 (Desktop { id, setup }) qui verrouille la boucle d'exécution (Étape 4) :
    • tool.execute.before : bloque tout appel à merge_pull_request et force HTTPS sur webfetch via replaceInPlace.
    • tool.execute.after : filtre la sortie brute de chaque outil pour masquer les tokens secrets (ghp_..., sk-...) avant qu'ils ne soient injectés dans le message role: "tool" envoyé au LLM !

Code Source du Plugin Industrialisé : ~/.config/opencode/plugins/security-interceptor.ts

/**
 * Plugin OpenCode Industrialisé (Dual V1 + V2) : Pare-feu Pre-Tool & DLP Post-Tool
 */

// Mutation in-place : conserve la référence mémoire de l'objet target dans le moteur OpenCode
function replaceInPlace(target: Record, next: Record) {
  for (const key of Object.keys(target)) delete target[key]
  Object.assign(target, next)
}

// Expression régulière de Data Loss Prevention (DLP) contre la fuite de secrets vers le LLM
const SECRET_REGEX = /(ghp_[A-Za-z0-9]{30,}|github_pat_[A-Za-z0-9_]{40,}|sk-[A-Za-z0-9]{20,})/g

function redactSecrets(text: string): string {
  return text.replace(SECRET_REGEX, "[SECRET_REDACTED_BY_PLUGIN]")
}

// ============================================================================
// 1. Moteur OpenCode V1 (Export d'une fonction asynchrone retournant les Hooks)
// ============================================================================
const SecurityInterceptorPlugin = async () => {
  const callTimings = new Map()

  return {
    // Injection dans le System Prompt (Étape 1)
    "experimental.chat.system.transform": async (_input: any, output: { system: string[] }) => {
      output.system.push(
        "=== [GOUVERNANCE RUNTIME : SecurityInterceptor] ===\n" +
        "- La fusion directe de PR (merge) est bloquée par le runtime.\n" +
        "- Les secrets présents dans les sorties d'outils sont masqués automatiquement."
      )
    },

    // Forçage déterministe de la température (Étape 1)
    "chat.params": async (_input: any, output: { temperature: number }) => {
      output.temperature = 0.1
    },

    // Intercepteur AVANT exécution de l'outil (Pre-Tool Firewall)
    "tool.execute.before": async (
      input: { tool: string; sessionID: string; callID: string },
      output: { args: Record }
    ) => {
      callTimings.set(input.callID, Date.now())

      // A. Blocage déterministe d'un outil MCP sensible
      if (input.tool === "github-mcp-server_merge_pull_request") {
        throw new Error(
          `[SecurityInterceptor] BLOCKED: L'outil '${input.tool}' est interdit aux agents IA.`
        )
      }

      // B. Réécriture in-place des arguments : mise à niveau HTTP -> HTTPS
      if (input.tool === "webfetch" && typeof output.args?.url === "string") {
        if (output.args.url.startsWith("http://") && !output.args.url.includes("127.0.0.1")) {
          replaceInPlace(output.args, {
            ...output.args,
            url: output.args.url.replace("http://", "https://"),
          })
        }
      }
    },

    // Intercepteur APRÈS exécution de l'outil (Post-Tool Secret Redaction)
    "tool.execute.after": async (
      input: { tool: string; sessionID: string; callID: string; args: any },
      output: { title: string; output: string; metadata: any }
    ) => {
      const elapsed = Date.now() - (callTimings.get(input.callID) ?? Date.now())
      callTimings.delete(input.callID)

      // Purge les secrets dans output.output AVANT la création du message role: "tool" !
      if (typeof output.output === "string") {
        output.output = redactSecrets(output.output)
      }
      output.title = `${output.title || input.tool} [Audité en ${elapsed}ms]`
    },
  }
}

// ============================================================================
// 2. Moteur OpenCode V2 Desktop ({ id, setup } avec fonction de nettoyage)
// ============================================================================
;(SecurityInterceptorPlugin as any).id = "security-interceptor"
;(SecurityInterceptorPlugin as any).setup = async (ctx: any) => {
  let active = true

  await ctx.tool.hook("execute.before", async (event: any) => {
    if (!active) return
    if (event.tool === "github-mcp-server_merge_pull_request") {
      throw new Error("[SecurityInterceptor V2] Fusion directe de PR interdite.")
    }
    if (event.tool === "webfetch" && typeof event.input?.url === "string") {
      if (event.input.url.startsWith("http://") && !event.input.url.includes("127.0.0.1")) {
        replaceInPlace(event.input, {
          ...event.input,
          url: event.input.url.replace("http://", "https://"),
        })
      }
    }
  })

  await ctx.tool.hook("execute.after", async (event: any) => {
    if (!active || event.status !== "completed" || !event.result) return
    if (typeof event.result.output === "string") {
      event.result.output = redactSecrets(event.result.output)
    }
  })

  // Cleanup appelé lors du déchargement ou Hot-Reload du plugin
  return async () => {
    active = false
  }
}

export default {
  id: (SecurityInterceptorPlugin as any).id,
  server: SecurityInterceptorPlugin,
  setup: (SecurityInterceptorPlugin as any).setup,
}

3. Comparaison Architecturale : Plugins JS/TS OpenCode vs Hooks Cursor (.cursor/hooks.json)

Comment Cursor implémente-t-il ces mêmes garde-fous déterministes ? Alors qu'OpenCode exécute des modules JS/TS in-process avec accès direct aux objets mémoire, Cursor déclenche des scripts externes via .cursor/hooks.json communiquant en JSON sur stdin / stdout :

Dimension Technique OpenCode (~/.config/opencode/plugins/*.ts) Cursor (.cursor/hooks.json)
Modèle d'Exécution In-Process (Bun/Node) : Fonctions JS/TS asynchrones partageant le runtime avec accès direct au SDK client et au shell $. Subprocess Externe : Spawne un exécutable/script shell à chaque événement et lui passe un JSON sur stdin.
Création de Nouveaux Outils Oui : Via tool({ description, args: tool.schema, execute }) directement dans le plugin. Non : Les hooks Cursor observent/bloquent uniquement ; pour ajouter des outils dans Cursor, il faut créer un serveur MCP.
Interception Pré-Outil Hook "tool.execute.before" (mutation in-place de output.args ou throw new Error). Événements preToolUse / beforeShellExecution / beforeMCPExecution retournant {"permission": "deny"} sur stdout.
Transformation du Prompt / Post-Outil Hooks "experimental.chat.system.transform" et "tool.execute.after" (mutation de output.output). Événements beforeSubmitPrompt, afterFileEdit, stop.
