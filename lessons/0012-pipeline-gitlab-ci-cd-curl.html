L'Agent Headless en Production : Pipeline GitLab CI/CD Automatisé (cURL, jq & opencode run)

Déployons tout ce que nous avons appris dans un conteneur éphémère GitLab CI/CD pour auditer automatiquement chaque Merge Request, résister aux erreurs réseau (HTTP 429) et bloquer les régressions critiques.

📖 Fil Rouge Architectural • Chapitre 12
Grâce à l'Étape 11 (strict: true), nous savons obtenir un verdict JSON déterministe. Il est temps d'industrialiser cette brique dans un runner **GitLab CI/CD** sans aucune intervention humaine. Mais dans un script Bash CI/CD, trois pièges mortels attendent le développeur : l'injection involontaire de guillemets/retours à la ligne provenant d'un `git diff` dans le JSON cURL, les limites de débit API (`HTTP 429 Too Many Requests`), et le choix entre un appel REST pur (`cURL`) et un agent CLI headless (`opencode run` / `cursor-agent`).
🔴 Le Problème Technique : Échappement JSON & Résilience Réseau en CI
1. Concaténer une variable $GIT_DIFF contenant des guillemets ", des antislashs \ et des sauts de ligne directement dans une chaîne curl -d "{...}" brise systématiquement la syntaxe JSON.
2. Aux heures de pointe, l'API d'inférence peut renvoyer HTTP 429 (Rate Limit) ou HTTP 502/503, faisant échouer le pipeline CI pour une erreur transitoire.
🟢 La Solution Architecturale : Encodage jq -n --arg & Exponential Backoff
1. Construire l'intégralité du payload de requête avec jq -n --arg diff "$GIT_DIFF" qui échappe mathématiquement tous les caractères spéciaux RFC 8259.
2. Configurer curl --retry 4 --retry-delay 2 --retry-all-errors (Exponential Backoff) ou invoquer l'agent en mode non-interactif (opencode run).

2. Code Source Complet de Production : .gitlab-ci.yml

Voici le fichier .gitlab-ci.yml prêt pour la production, utilisant uniquement curl, git et jq dans une image Alpine ultra-légère : 

stages:
  - ai-quality-gate

ai_security_review:
  stage: ai-quality-gate
  image: alpine:3.20
  rules:
    - if: $CI_PIPELINE_SOURCE == "merge_request_event"
  before_script:
    - apk add --no-cache curl git jq
  script:
    - echo "🔍 Récupération du diff de la Merge Request..."
    - git fetch origin "$CI_MERGE_REQUEST_TARGET_BRANCH_NAME" --depth=50
    - RAW_DIFF=$(git diff "origin/${CI_MERGE_REQUEST_TARGET_BRANCH_NAME}...HEAD" | head -c 60000)

    - |
      if [ -z "$RAW_DIFF" ]; then
        echo "Aucun changement détecté."
        exit 0
      fi

    - echo "📦 Construction sécurisée du payload JSON via jq..."
    - |
      jq -n \
        --arg diff "$RAW_DIFF" \
        '{
          model: "gpt-4o-mini",
          temperature: 0.0,
          messages: [
            {
              role: "system",
              content: "Tu es un auditeur DevSecOps. Analyse ce git diff et signale uniquement les failles de sécurité ou bugs critiques avérés."
            },
            {
              role: "user",
              content: $diff
            }
          ],
          response_format: {
            type: "json_schema",
            json_schema: {
              name: "ci_gate_verdict",
              strict: true,
              schema: {
                type: "object",
                properties: {
                  blocking: { type: "boolean" },
                  severity: { type: "string", enum: ["NONE", "LOW", "HIGH", "CRITICAL"] },
                  summary: { type: "string" }
                },
                required: ["blocking", "severity", "summary"],
                additionalProperties: false
              }
            }
          }
        }' > payload.json

    - echo "🚀 Appel résilient à l'API d'inférence (Exponential Backoff)..."
    - |
      curl -sS --fail-with-body \
        --retry 4 --retry-delay 2 --retry-all-errors \
        https://api.openai.com/v1/chat/completions \
        -H "Content-Type: application/json" \
        -H "Authorization: Bearer $OPENAI_API_KEY" \
        -d @payload.json > response.json

    - echo "📊 Analyse du verdict structuré..."
    - VERDICT=$(jq -r '.choices[0].message.content' response.json)
    - BLOCKING=$(echo "$VERDICT" | jq -r '.blocking')
    - SEVERITY=$(echo "$VERDICT" | jq -r '.severity')
    - SUMMARY=$(echo "$VERDICT" | jq -r '.summary')

    - echo " Sévérité : $SEVERITY | Résumé : $SUMMARY"
    - |
      if [ "$BLOCKING" = "true" ]; then
        echo "❌ BLOCKED: Une faille critique empêche la fusion de cette Merge Request."
        exit 1
      fi
    - echo "✅ Aucun problème bloquant détecté."

3. Alternative Agentique Complète en CI : cURL pur vs opencode run (Headless Mode)

Quand faut-il utiliser cURL direct (comme ci-dessus) et quand faut-il lancer l'agent complet en mode non-interactif (Headless CLI) dans votre CI/CD ?

Approche en CI/CD Commande Exécutée Cas d'Usage Optimal
1. Appel Statique cURL + jq curl ... -d @payload.json Ultra-rapide (< 3s), zéro dépendance Node/Bun : idéal quand tout le contexte tient dans le git diff fourni en entrée.
2. OpenCode Headless CLI opencode run -m anthropic/claude-sonnet-4 "Utilise @security-auditor pour vérifier la PR" --format json Idéal quand l'agent CI a besoin d'explorer d'autres fichiers du dépôt (grep, read), de charger vos Skills (Étape 8), vos Plugins JS/TS (Étape 10) ou vos serveurs MCP (Étape 5) !
