Diviser pour Régner : Agents Primaires (Build / Plan) & Sous-Agents (mode: subagent)

Comment éviter qu'une recherche exploratoire dans 60 fichiers ne pollue définitivement la mémoire de votre session principale ? Découvrez l'isolation de fenêtre de contexte par sous-agents dans OpenCode et Cursor.

📖 Fil Rouge Architectural • Chapitre 9
Avec les Rules (Étape 7) et les Skills (Étape 8), notre agent démarre avec un contexte propre et léger. Mais dès que nous lui confions une tâche d'envergure — « Trouve où est gérée la révocation des refresh tokens dans ce monorepo de 400 fichiers, puis refactorise le module » — l'agent exécute 25 appels grep et read. Son tableau messages[] gonfle à 90 000 tokens de code non pertinent avant même d'écrire la première ligne de code !
🔴 Le Problème Technique : La Pollution de Contexte (Context Pollution)
Dans une session unique (Single-Agent Loop), tous les résultats intermédiaires des outils (role: "tool") restent empilés dans le tableau messages[].
1. Les fichiers lus par erreur pendant la fouille encombrent la Context Window jusqu'à la fin de la session.
2. Un agent disposant de tous les droits d'écriture peut modifier du code prématurément alors qu'on souhaitait uniquement établir un plan d'architecture.
🟢 La Solution Architecturale : Agents Primaires & Sous-Agents Isolés
OpenCode et Cursor résolvent ce problème par deux mécanismes :
1. Séparation des Agents Primaires (Build vs Plan) : Un mode d'analyse strict en lecture seule séparé du mode d'écriture.
2. Délégation aux Sous-Agents (mode: subagent) : L'agent principal spawne une session enfant dotée de son propre tableau messages[] vierge via l'outil task. Le sous-agent absorbe les 80 000 tokens de recherche, puis est détruit en ne renvoyant qu'une synthèse de 300 tokens au parent !

1. Les Deux Catégories d'Agents dans OpenCode (Documentation Officielle)

Selon la documentation officielle d'OpenCode (opencode.ai/docs/agents), il existe deux types d'agents, configurables via la propriété mode :

Catégorie Agents Intégrés (Built-in) dans OpenCode Équivalent dans Cursor Fonctionnement & Permissions
1. Primary Agents
(mode: primary)		 • build (défaut)
• plan (bascule via touche Tab) 		• Agent Mode
• Plan / Ask Mode 		Interagissent directement avec l'utilisateur dans la session principale. L'agent plan désactive les modifications de fichiers (edit: deny, bash: ask/deny) pour analyser sans risque.
2. Subagents
(mode: subagent)		 • explore (rapide, lecture seule : grep, glob, read)
• general (recherche multi-étapes complète) 		Sous-agents intégrés et personnalisés dans .cursor/agents/*.md Travaillent dans une fenêtre de contexte isolée. Invoqués automatiquement par l'agent primaire via l'outil task, ou manuellement par l'utilisateur avec @explore / @general.

2. Comment Créer et Déposer un Sous-Agent Personnalisé (Code Source Réel)

Vous pouvez créer vos propres agents et sous-agents (ex: un auditeur de sécurité en lecture seule utilisant un modèle spécialisé) de deux manières : en fichier Markdown (recommandé) ou dans opencode.jsonc.

Où déposer vos fichiers d'agents ?

  • OpenCode (Projet) : .opencode/agents/<nom-agent>.md
  • OpenCode (Global) : ~/.config/opencode/agents/<nom-agent>.md
  • Cursor (Projet / Global) : .cursor/agents/<nom-agent>.md ou ~/.cursor/agents/<nom-agent>.md
📄 Méthode 1 : Fichier .opencode/agents/security-auditor.md
---
description: >-
  Auditeur de sécurité spécialisé dans la détection de failles OWASP,
  injections SQL et secrets exposés. À invoquer avant toute Pull Request.
mode: subagent
model: anthropic/claude-sonnet-4-20250514
temperature: 0.1
tools:
  read: true
  grep: true
  glob: true
  write: false
  edit: false
  bash: false
permission:
  edit: deny
  bash: deny
---

Tu es un ingénieur sécurité senior. Analyse le code demandé en lecture seule.
1. Recherche les vulnérabilités (injections, XSS, SSRF, secrets hardcodés).
2. Ne modifie jamais aucun fichier.
3. Renvoie un rapport concis classé par sévérité (Critique, Haute, Moyenne) avec le fichier et la ligne exacte.
⚙️ Méthode 2 (OpenCode JSON) : opencode.jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "agent": {

      "temperature": 0.1,
      "prompt": "{file:./prompts/security-audit.txt}",

        "edit": false,

}

3. Les 2 Modes d'Invocation : Explicite (@mention) vs Automatique (Outil task)

  1. Invocation Explicite par le Développeur : Dans le prompt TUI/Desktop d'OpenCode ou dans le chat Cursor, tapez directement @security-auditor Analyse le dossier src/auth/. Vous pouvez ensuite naviguer entre la session parente et les sessions des sous-agents pour inspecter leur travail.
  2. Délégation Automatique par l'Agent Primaire : L'agent primaire (Build) voit la liste des sous-agents disponibles et leurs champs description dans la définition de son outil natif task. Lorsqu'il juge qu'une sous-tâche nécessite une exploration lourde ou un audit, il émet un tool_call vers task(subagent_type: "security-auditor", prompt: "...") !
