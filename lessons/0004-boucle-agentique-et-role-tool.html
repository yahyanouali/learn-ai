La Boucle Agentique (ReAct) : Exécution Locale, Permissions & Rôle tool

Découvrez le cœur battant d'OpenCode et de Cursor : la boucle while (finish_reason === "tool_calls") qui transforme un simple modèle prédictif en un agent autonome capable d'agir, d'observer et de s'auto-corriger.

📖 Fil Rouge Architectural • Chapitre 4
À l'Étape 3, notre requête s'est interrompue sur finish_reason: "tool_calls" avec l'identifiant call_abc123xyz demandant la lecture de src/auth.ts. Mais l'API étant stateless (Étape 1), le serveur d'OpenAI a fermé la requête HTTP et n'attend rien ! C'est maintenant à notre runtime local de vérifier les droits d'accès, d'exécuter l'opération sur le disque, et d'assembler une nouvelle requête HTTP contenant l'historique complet augmenté du résultat.
🔴 Le Problème Technique
Trois défis critiques se posent au runtime local lorsqu'il reçoit un tool_call :
1. Sécurité : Que se passe-t-il si le LLM demande d'exécuter bash("rm -rf /") ou de lire .env ?
2. Corrélation : Si le LLM a demandé 3 outils en parallèle, comment associer chaque sortie au bon appel ?
3. Continuité : Quand la boucle d'appels d'outils doit-elle s'arrêter ?
🟢 La Solution Architecturale
1. Moteur de Permissions (RBAC local) : Chaque appel traverse une matrice allow / ask / deny avant exécution.
2. Message "role": "tool" : Le résultat est encapsulé dans un message portant obligatoirement la clé étrangère "tool_call_id": "call_abc123xyz".
3. Boucle ReAct (Reason + Act) : Tant que le modèle renvoie finish_reason: "tool_calls", l'agent empile les messages assistant + tool et rappelle l'API, jusqu'à obtenir finish_reason: "stop".

1. Le Second Appel HTTP : Injecter le Message "role": "tool"

Une règle protocolaire stricte d'OpenAI impose que tout message "role": "tool" soit immédiatement précédé du message "role": "assistant" contenant le tool_calls[] correspondant. Omettre le message de l'assistant ou inverser l'ordre provoque une erreur HTTP 400 Bad Request.

3. Gouvernance & Permissions : OpenCode (opencode.jsonc) vs Cursor

Pour éviter qu'une hallucination ou une attaque par Prompt Injection ne compromette votre machine, OpenCode et Cursor implémentent un pare-feu de permissions granulaire par motif (glob pattern) : 

// Extrait réel de ~/.config/opencode/opencode.jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "permissions": [
    { "action": "edit",  "resource": "*",           "effect": "ask"   },
    { "action": "shell", "resource": "git status *", "effect": "allow" },
    { "action": "shell", "resource": "git diff *",   "effect": "allow" },
    { "action": "shell", "resource": "git push *",   "effect": "deny"  },
    { "action": "read",  "resource": "*.env*",       "effect": "ask"   }
  ]
}
Mécanisme de Sécurité OpenCode (Documentation Officielle) Cursor (Documentation Officielle)
Niveaux de décision allow (exécution directe), ask (validation humaine requise), deny (bloqué). Mode normal (demande confirmation sur terminal/édition hors workspace) vs Auto-Run Mode (anciennement Yolo Mode).
Filtrage de commandes Shell Règles permissions[] ordonnées avec motifs glob sur action: "shell" dans opencode.jsonc ou par agent. Command Allowlist et Denylist configurables dans Cursor Settings > Features > Chat & Agent.
Protection des fichiers sensibles Règle {"action": "read", "resource": "*.env*", "effect": "ask"}. Fichier .cursorignore (bloque l'indexation et la lecture par l'agent).

4. Gestion des Erreurs & Troncature des Sorties (Output Pruning)

Que fait l'agent si la commande exécutée échoue (code de sortie exit 1) ou renvoie 50 Mo de logs ?

  • Auto-guérison (Self-Healing) : L'agent ne plante pas sur une erreur d'outil. Il capture stderr et le renvoie dans le message "role": "tool". En lisant le message d'erreur du compilateur ou du shell, le LLM corrige ses arguments au tour suivant !
  • Troncature (Context Pruning) : Pour éviter une erreur context_length_exceeded, OpenCode tronque automatiquement les sorties d'outils dépassant un seuil (ex: 2 000 lignes ou ~30 KB) et sauvegarde la sortie complète sur disque si l'agent a besoin d'y faire un grep ciblé.
