Gouverner le Comportement : Les Rules (AGENTS.md, instructions & .cursor/rules/*.mdc)

Notre agent possède désormais un moteur d'inférence (Acte I) et un écosystème d'outils extensible (Acte II). Mais il souffre d'un défaut majeur : à chaque nouvelle session, il ignore tout des conventions architecturales de votre équipe.

📖 Fil Rouge Architectural • Chapitre 7
Imaginez recruter un développeur senior prodige qui maîtrise tous vos outils (Git, Docker, GitHub MCP), mais qui perd intégralement la mémoire chaque matin en arrivant au bureau : il utilise npm au lieu de bun, écrit des composants React en classes au lieu de hooks, et oublie vos règles de sécurité. Comment doter notre agent stateless (Étape 1) d'une mémoire déclarative persistante ?
🔴 Le Problème Technique
Comme chaque nouvelle session de chat repart d'un tableau messages[] vierge, l'utilisateur devrait répéter manuellement dans chaque prompt : « Utilise Bun, lance les tests avec vitest, n'utilise jamais any en TypeScript... ». En équipe, cette dérive génère du code incohérent d'un développeur à l'autre.
🟢 La Solution Architecturale : Les Rules (Instructions Système)
Le runtime scanne automatiquement des fichiers Markdown versionnés dans Git (AGENTS.md dans OpenCode et Cursor, ou .cursor/rules/*.mdc dans Cursor) et les concatène de manière déterministe dans le message "role": "system" dès l'ouverture de la session.

1. Comment OpenCode découvre et résout les Rules (Documentation Officielle)

Au démarrage d'une session (ou via la commande /init qui analyse le dépôt pour générer un AGENTS.md initial), OpenCode agrège les règles selon une hiérarchie stricte de découverte :

  1. Règles Projet (AGENTS.md) : OpenCode part du répertoire courant et remonte l'arborescence des dossiers (directory traversal) jusqu'à la racine du worktree Git pour charger chaque AGENTS.md trouvé (fallback automatique sur CLAUDE.md si présent, désactivable via OPENCODE_DISABLE_CLAUDE_CODE=1).
  2. Règles Globales Utilisateur (~/.config/opencode/AGENTS.md) : Vos préférences personnelles appliquées à tous vos projets (fallback sur ~/.claude/CLAUDE.md).
  3. Tableau "instructions" dans opencode.jsonc : Permet d'inclure des fichiers Markdown existants du dépôt, des motifs glob ou même des URLs distantes partagées à l'échelle de l'entreprise !
// Déclaration officielle dans opencode.jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "instructions": [
    "CONTRIBUTING.md",
    "docs/architecture-guidelines.md",
    "packages/*/AGENTS.md",
    "https://raw.githubusercontent.com/mon-org/shared-rules/main/typescript-strict.md"
  ]
}

2. Comparaison Technique : OpenCode vs Cursor (.cursor/rules/*.mdc)

Alors qu'OpenCode privilégie le standard interopérable AGENTS.md couplé au tableau instructions (et aux règles par agent), Cursor propose en complément le format .mdc (Markdown Cursor) dans le dossier .cursor/rules/ doté d'un frontmatter YAML contrôlant le mode d'injection :

📄 Standard AGENTS.md (OpenCode & Cursor)
# Architecture & Commandes du Projet
- Package manager : `bun` (ne jamais utiliser `npm` ou `yarn`).
- Tests unitaires : `bun test src/` avant tout commit.

# Standards TypeScript
- Mode strict activé : interdiction formelle du type `any`.
- Privilégier les unions discriminées et les schémas `zod`.
- Gestion d'erreurs explicite sans bloc `catch` silencieux.
📄 Règle Scopée Cursor (.cursor/rules/react.mdc)
---
description: Standards pour les composants React et Tailwind
globs: "src/components/**/*.tsx"
alwaysApply: false
---

# Règles Composants Frontend
- Utiliser exclusivement des composants fonctionnels typés.
- Extraire toute logique d'état complexe dans un hook `use*`.
- Ne jamais écrire de CSS inline : utiliser les classes Tailwind.
Mode d'Activation de la Règle Implémentation dans OpenCode Implémentation dans Cursor (.cursor/rules/*.mdc)
1. Toujours Active (Global / Root) AGENTS.md à la racine + ~/.config/opencode/AGENTS.md + instructions[]. AGENTS.md à la racine ou fichier .mdc avec alwaysApply: true.
2. Activation par Motif de Fichier (File-Scoped / Glob) Chargement contextuel des AGENTS.md de sous-dossiers ou motifs glob dans instructions. Propriété YAML globs: "src/api/**/*.ts" (injectée dès qu'un fichier correspondant est ouvert/ciblé).
3. Activation Sémantique (Agent-Requested) Délégué aux Skills (Étape 8) ou aux sous-agents spécialisés (Étape 9). alwaysApply: false sans glob : l'agent lit la description et décide d'inclure la règle.
4. Invocation Manuelle Référence directe au fichier avec @ chemin/regle.md dans le prompt. Mention explicite @nom-de-regle dans la fenêtre de chat.

3. Mécanique Exacte d'Injection dans le Prompt HTTP & Budget de Tokens

Que signifie concrètement « charger une règle » au niveau du payload HTTP POST /v1/chat/completions ? Il n'y a aucune magie : c'est une opération de concaténation de chaînes de caractères encadrée par un plafond de sécurité (Token Budget) :

flowchart TD Start["Démarrage de Session / Nouveau Tour"] --> Scan["Découverte des fichiers de Règles
(AGENTS.md, ~/.config/opencode/AGENTS.md, instructions)"] Scan --> CheckSize{"Taille cumulée des règles
inférieure au Budget (~20 000 tokens)
et fichier inférieur à 24 KB ?"} CheckSize -->|"OUI (Cas nominal)"| Inline["Inlining Littéral :
Le texte Markdown intégral est copié-collé
dans messages[0] (role: 'system')"] CheckSize -->|"NON (Dépassement de budget)"| Pointer["Rétrogradation en Pointeurs (Demotion) :
Seul le chemin file:///chemin/AGENTS.md
est inséré dans role: 'system'"] Inline --> Cache["Instructions actives en permanence
dès le premier tour de l'agent"] Pointer --> OnDemand["L'agent appelle l'outil read à la demande
s'il a besoin de consulter la règle"]
